# Concept Intake and Readiness Guide

Use this guide only while preparing a full design project. Its purpose is to prevent premature visual decisions, not to turn intake into a long questionnaire.

## Required Brief

The brief is ready when each field below has an answer, a supported inference, or a user-approved assumption:

| Field | Capture | Ask only when missing |
| --- | --- | --- |
| Product core | What it helps people do; primary job to be done | The product idea is vague or feature-led |
| Audience and moment | Who uses it, in what emotional and practical context | The desired tone could vary by audience |
| Platform and scope | iOS, Android, web, or cross-platform; core screens or flow | UI conventions or density depend on it |
| Brand feeling | Desired impression and important tension | A style might be attractive but emotionally wrong |
| Visual evidence | Existing screens, references, color preference, or anti-reference | No evidence anchors the aesthetic direction |
| Constraints | Accessibility, existing brand/tech, delivery needs, non-negotiables | The final system could become infeasible |

## Intake Behavior

- Start with what the user has already supplied. Do not ask them to repeat it.
- Ask the missing field with the greatest impact on the next decision, one at a time.
- Offer two or three answer choices only when they reduce ambiguity; always allow a concise free-form answer.
- After every 2–3 answers, give a short "brief so far" recap and identify the one remaining critical gap.
- If the user does not know, propose a concrete assumption and ask for confirmation. Do not silently invent a user, platform, or product scope.

## Ready-to-Design Check

Before final directions, state this compact check internally and, if useful, to the user:

```markdown
Brief status: ready
- Product / audience / platform / scope: confirmed
- Desired feeling and visual evidence: confirmed
- Constraints and assumptions: confirmed
```

If any line is not confirmed, continue intake. A screenshot can confirm visual language, but it does not by itself confirm the product's audience, intent, or constraints.

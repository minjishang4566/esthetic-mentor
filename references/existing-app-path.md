# Existing App Path

Use this guide only after a user shares their own app or screens. The objective is to help them understand what they have before deciding how to evolve it.

## First Question

Ask the starting-choice question if it is unanswered:

> Do you want to build a more original visual identity from this app, or use selected existing apps as references for transferable principles?

Do not assume that a request for "top designers" or "similar apps" means the user wants imitation. A user may be looking for language to understand their existing work.

## Response Order

1. **Current style definition**: give one working name, a familiar anchor only if it clarifies, and 2–3 observations grounded in the screenshots.
2. **Keep**: name one existing strength that supports the product.
3. **Improve**: give 1–3 points in `evidence -> consequence -> repair` form, ordered by leverage.
4. **Next branch**: based on the user's choice, either guide original style creation or request their selected app references.

Use a descriptive name that explains the product's actual visual language. Avoid a pile of labels such as “X + Y + Z” unless each influence controls a distinct and necessary part of the system.

## Two Branches

### Original Visual Identity

After defining the current style, ask what must be retained: for example, warmth, softness, clarity, playfulness, or restraint. Then use the concept-readiness gate and visual-source workflow to develop an original Visual DNA. Existing apps may be discussed as market context, but they are not the blueprint.

### Existing-App References

Invite the user to share any products, screenshots, links, or specific qualities they admire. For each supplied reference, distinguish:

- transferable principle: hierarchy, color-role discipline, form restraint, onboarding rhythm, or state design;
- non-transferable identity: brand assets, illustrations, distinctive layouts, and proprietary product voice.

Recommend how to adapt the principle to the user's own Taste Profile. Do not present a competitor as a target to reproduce.

## Compact Output Shape

```markdown
## Current Direction: [working name]
[2–3 evidence-based observations]

**Keep:** [one strength]
**Improve first:**
1. [evidence] -> [consequence] -> [repair]
2. ...

**Next:** [one question based on original-identity or reference branch]
```

Keep the first response short. A complete audit, external research, reference images, or a final direction comes only after the user chooses the branch and the brief is ready.
